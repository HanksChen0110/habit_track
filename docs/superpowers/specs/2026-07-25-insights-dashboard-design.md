# “循迹”洞察 Dashboard 设计

> 状态：设计已确认，待形成实施计划  
> 日期：2026-07-25  
> 适用项目：`G:\FDE\habit_track`  
> 关联设计基线：`docs/design/high-fidelity-prototype.md`

## 1. 背景与结论

现有产品的“今天”负责每日记录，“本周”负责短周期复盘，“管理”负责习惯配置和本地数据维护。新增的 Dashboard 不接管这些职责，而是作为独立一级页面“洞察”，负责跨习惯、跨时间的数据观察与规划。

一级导航调整为：

`今天 / 本周 / 洞察 / 管理`

洞察页采用“总览后下钻”的信息架构：

1. 先回答整体表现如何。
2. 再回答表现如何随时间变化。
3. 再展示哪些习惯经常在同一天表现一致。
4. 最后允许用户进入单个习惯或一对习惯的详情。

Dashboard 使用现有 `Store` 数据即可实现，不修改 `Store { version: 1, habits, completions }`，也不增加后端、账号或新业务字段。

## 2. 产品职责边界

### 2.1 今天

- 快速调整当天完成量。
- 修正最近七天内的漏记。
- 展示当天计划和即时进度。

### 2.2 本周

- 复盘当前或历史自然周。
- 展示周执行率、逐日差异和紧邻周环比。
- 回答“这一周是否偏离计划”。

### 2.3 洞察

- 汇总 7、30、90 天的整体表现。
- 展示整体与单个习惯的时间趋势。
- 发现两项习惯的同日共现线索。
- 对习惯表现进行排序和下钻。
- 回答“长期发生了什么、哪些数据可能一起变化”。

### 2.4 管理

- 创建、改名、设置目标和归档习惯。
- 解释目标锁定、生效日期等业务规则。
- 导入、导出和迁移本地数据。
- 回答“如何修改计划和维护数据”。

洞察与管理共享同一份数据，但功能职责重合度较低。洞察中只提供“调整计划”的定向跳转，不直接修改名称、目标或归档状态。导入和完整替换数据等高风险操作不得出现在分析图表旁。

## 3. 页面信息架构

页面路由为 `/insights`，使用现有 Hash Router。

### 3.1 页面标题与全局范围

- 标题：“看见习惯如何一起变化”。
- 副标题显示统计截止日期、习惯数量和观察窗口。
- 时间范围：`7 天 / 30 天 / 90 天`。
- 默认范围：最近 30 个已经结束的自然日。
- 今天显示为“进行中”，不进入长期趋势和环比。

时间范围切换采用参考组件中的聚焦边框和内容过渡，但继续使用“循迹”的淡紫强调色。

### 3.2 总览指标

首屏展示四项指标：

1. 整体执行率，以及与紧邻等长窗口相比的百分点变化。
2. 有计划日期数量。
3. 表现最佳的习惯及其执行率。
4. 近期最需要关注的习惯及其变化。

如果没有足够的上一周期数据，环比显示“暂无可比周期”，不得显示 `0%` 或虚构变化。

“表现最佳”和“需要关注”只从达到最低观察量的习惯中选择：

- 7 天窗口至少有 3 个有效计划日。
- 30 天和 90 天窗口至少有 7 个有效计划日。

未达到门槛的习惯仍出现在习惯表现列表，但标记“数据积累中”，不进入首屏判断。

### 3.3 执行趋势

- 纵轴固定为 `0–100%`。
- 主线展示全部有效习惯的加权整体执行率。
- 允许同时叠加一个选中习惯，避免多条曲线拥挤。
- 点击习惯排行、共现矩阵或详情项，可改变当前选中习惯。
- 7 天范围展示每日值。
- 30 天范围展示每日值与 7 日平滑趋势。
- 90 天范围按自然周聚合。

原始值必须仍可通过焦点或点击读取，平滑线不能替代原始数据。

### 3.4 本期线索

趋势图旁展示当前窗口中最值得关注的一条可解释线索，例如：

- “阅读与运动经常在同一天达标。”
- “早睡与喝水经常在同一天未达标。”
- “运动改善，但早睡同期下降。”

线索必须同时显示：

- 共同有效日期数量。
- 具体结果比例。
- 样本等级。
- “伴随关系不代表因果”的提示。

当没有达到样本门槛的关系时，展示“继续记录后，这里会出现习惯之间的伴随线索”，不得强行选出最强关系。

### 3.5 共现矩阵

矩阵按习惯两两组合展示，提供三个分析视角：

1. 同时达标。
2. 同时未达标。
3. 表现相反。

三个视角使用 Ruixen 参考组件的聚焦式选项切换。矩阵颜色只编码当前视角的比例，不把三种结果压缩成难以解释的单一相关系数。

点击任一矩阵单元后打开两项习惯的下钻详情，展示三种结果的完整构成和对应日期。

### 3.6 习惯表现

习惯列表展示：

- 当前窗口执行率。
- 与上一等长窗口相比的百分点变化。
- 趋势状态：上升、稳定、下降或暂无可比数据。
- 有效计划日期数量。

默认按“需要关注程度”排序：明显下降优先，其次是较低执行率，再其次是稳定和改善项。用户可以切换为按执行率或名称排序，但本轮不提供任意字段组合和复杂筛选器。

### 3.7 下钻详情

下钻留在洞察页内，不新增独立详情路由：

- 点击 KPI：打开对应指标的计算说明和时间构成。
- 点击趋势点：展示该日期各习惯的计划量与完成量。
- 点击单个习惯：展示该习惯在当前窗口的趋势和有效日期。
- 点击矩阵单元：展示两项习惯的三类共现构成。

桌面使用右侧详情抽屉；手机使用底部详情面板。关闭后保留时间范围、选中习惯和滚动位置。

需要改名、修改目标或归档时，详情内提供“前往管理”入口，并携带习惯 ID，让管理页直接聚焦相应习惯。

## 4. 数据合同

### 4.1 观察窗口

- 以浏览器本地日期为准。
- 当前日期不进入已完成观察窗口。
- 7、30、90 天均指连续自然日，不是“有记录的日期数”。
- 某日没有任何有效习惯时，该日为无计划日期，不进入执行率分母。
- 习惯只在 `createdOn <= date <= archivedOn` 时有效；未归档习惯没有结束日期。

该规则只用于长期洞察。现有“本周”页继续按已确认规格把今天计入进行中的周报，两者不互相修改。

### 4.2 执行率

单个习惯在观察窗口内：

`执行率 = 有效计划日实际完成量合计 ÷ 有效计划日目标量合计`

整体执行率：

`整体执行率 = 所有有效习惯实际完成量合计 ÷ 所有有效习惯目标量合计`

完成量继续限制在 `0..targetPerDay`。有效计划日没有 `Completion` 记录时，实际完成量为 0。

该口径与现有周报的加权计算保持一致，不对目标为 1 和目标大于 1 的习惯做无依据的等权平均。

### 4.3 环比

- 当前窗口与紧邻的上一等长窗口比较。
- 变化使用百分点 `pp`，不是百分比增长率。
- 任一窗口没有有效计划时不计算环比。
- 当前窗口与上一窗口分别按当时有效的习惯集合计算，不把尚未创建或已经失效的习惯补入历史。

### 4.4 同日共现

对任意两项习惯 A、B：

1. 只取 A、B 同时处于有效生命周期的日期。
2. 将每项习惯每日状态转换为二值：
   - `达标`：`count === targetPerDay`。
   - `未达标`：`count < targetPerDay`。
3. 统计：
   - `n11`：A、B 同时达标。
   - `n00`：A、B 同时未达标。
   - `n10 + n01`：一项达标、一项未达标。
4. 三种视角的比例均以共同有效日期数 `N` 为分母。

页面不使用“导致”“促进”“影响”等因果表述。

### 4.5 样本门槛

- `N < 7`：仅显示“数据积累中”，不参与排序。
- `7 <= N < 14`：允许查看，标记“初步线索”，不作为首页本期线索。
- `N >= 14`：可参与最强共现排序，但仍注明非因果。

如果多个组合并列，优先选择共同有效日期更多的组合；仍并列时按习惯名称稳定排序，避免每次渲染结果跳动。

样本门槛只是产品展示保护，不表示结果已经达到统计显著性。

## 5. 响应式设计

### 5.1 桌面端：1024px 及以上

- 沿用居中最大宽度画布和顶部胶囊导航。
- 四项总览指标同排。
- 趋势图与本期线索并列。
- 共现矩阵与习惯表现并列。
- 详情从右侧抽屉展开，主内容保留可见上下文。

### 5.2 手机与平板：320–1023px

- 底部固定四项导航：今天、本周、洞察、管理。
- 页面按“时间范围 → 总览 → 趋势 → 本期线索 → 共现矩阵 → 习惯表现”单列排列。
- 总览指标使用两列；320px 下仍保持两列，但文本可换行。
- 共现矩阵固定首列，并仅允许卡片内部横向滚动；页面本身不得横向滚动。
- 下钻使用底部详情面板。
- 所有可点击目标不小于 44 × 44 CSS 像素。

## 6. 视觉与组件融合

### 6.1 保留的“循迹”设计基线

- 背景：`#E9ECEA`。
- 主表面：白色或 94% 不透明白。
- 主文字和主操作：`#1E191A` / `#20191B`。
- 次级文字：`#666D69`。
- 强调色：`#A98BEE`。
- 淡紫表面：`#F2EDFF`。
- 分隔线：`#DFE3E0`。
- 危险操作：`#7F3036`。
- 使用项目内的 Noto Sans SC 字体。
- 面板依靠留白、边框和字体层级，阴影保持克制。

### 6.2 从 Efferd Dashboard 参考中吸收

- Dashboard 应用外壳。
- 总览指标卡片。
- 主图表、辅助洞察和列表的层级关系。
- 桌面高信息密度下的分区方式。

不复制其业务数据、头像、菜单或不存在于“循迹”的模块。

### 6.3 从 Ruixen Feature Section 参考中吸收

- 时间范围和共现视角的选中边框。
- 切换时的内容聚焦和轻量过渡。
- 大块内容区与控制区之间的视觉层级。

不复制其营销文案、图片背景和宣传页式布局。

### 6.4 技术边界

当前项目使用 React、Vite、TypeScript 和普通 CSS，不是 Tailwind/shadcn 项目。本次只参考组件风格，不迁移技术体系。

- 不新增 `/components/ui` 镜像目录。
- 继续使用现有 `src/components` 结构。
- `lucide-react` 已存在，继续复用。
- 不安装本轮不需要的 Radix Avatar、Separator、Collapsible、Dropdown Menu。
- 不为选中动画引入 Framer Motion，使用现有 CSS transition。
- 图表优先使用原生 SVG/CSS，不为本轮引入 Recharts。
- 不使用 Unsplash 或外部图片服务。

## 7. 状态与异常

### 7.1 无习惯

展示“创建第一个习惯后，这里会开始积累趋势”，提供前往管理页的单一入口。

### 7.2 有习惯但无完整日期

今天刚创建习惯时，显示“完成第一个完整记录日后生成洞察”，不把进行中的今天计算为 0%。

### 7.3 数据不足

- 总览可以基于已有完整日期展示。
- 环比不足时单独隐藏环比。
- 共现不足时显示积累进度和门槛说明。
- 不用占位随机数或示例结论冒充真实洞察。

### 7.4 本地数据更新

继续复用现有 `storage` 事件处理。其他标签页更新 Store 后：

- 重新计算当前洞察。
- 保留仍合法的筛选状态。
- 当前选中习惯已经归档或不存在时关闭详情。
- 提示“数据已在另一页面更新”。

### 7.5 数据损坏

继续进入现有恢复页，不在洞察页局部吞掉 Store 校验错误。

## 8. 无障碍与动效

- 图表提供可读标题、时间范围和文字摘要。
- 趋势点、矩阵单元和排序项支持键盘聚焦。
- 不只用颜色表达上升、下降、达标或样本等级。
- 详情抽屉和底部面板遵循现有 Modal 的焦点管理规则。
- 筛选结果变化通过可读状态播报。
- 切换、图线聚焦和面板展开使用 180–240ms 动效。
- `prefers-reduced-motion: reduce` 下取消位移和路径动画，只保留即时状态变化。

## 9. 验收标准

- 一级导航在桌面和手机均出现“洞察”，且不影响原有三个页面职责。
- 7、30、90 天范围结果符合本地自然日和习惯生命周期规则。
- 今天不进入长期趋势和环比。
- 整体执行率与现有周报加权口径一致。
- 新建或有效计划日过少的习惯不进入“最佳”和“需关注”指标。
- 环比只与紧邻等长窗口比较，并使用百分点。
- 共现只比较共同有效日期，三种结果总和为 100%。
- 样本门槛正确控制提示、排序和本期线索。
- 点击 KPI、趋势点、矩阵和习惯排行均可下钻。
- 前往管理时能聚焦相应习惯，但洞察页不直接修改业务规则。
- 320px、390px、768px、1024px 和 1440px 下无页面级横向滚动。
- 键盘、屏幕阅读器状态播报和减少动态效果可用。

## 10. 明确不做

- 不做因果分析、预测或 AI 建议。
- 不做跨日先后关系。
- 不新增习惯分类或标签字段。
- 不做任意日期范围选择。
- 不做用户自定义 Dashboard 布局。
- 不做后端、账号、云同步或跨设备数据。
- 不迁移 Tailwind/shadcn，不整套复制参考组件。
