## Why

现有习惯工具常把价值放在提醒、连续天数和长期图表上，却无法帮助个人用户用低负担的方式回看一周的实际执行。这个 MVP 要验证另一条路径：每天留下极短记录，每周据此看清整体执行率与日期规律，并将结论转化为下一周的一项调整。

现在已经完成产品定位、竞品分析和关键数据口径的确认，可以将这些结论固定为可实现、可验收的规格，避免后续开发重新引入账号、同步、提醒或复杂图表。

## What Changes

- 新增每日习惯的创建、计数记录、最近 7 天漏记纠正、名称修改与归档。
- 新增按周一至周日计算的周报，展示整体执行率、每日执行率、最佳/最差日期和与上周的整体执行率对比。
- 新增浏览器本地数据保存、完整 JSON 导入导出，以及导入与写入失败时保留原数据的保护。
- 新增响应式 Web/PWA 界面：手机和桌面均可完成记录、周报和管理，仅按设备调整信息层级。
- 新增 `UI-spec.md`，冻结已确认的视觉令牌、页面层级、双端断点、组件参数与无障碍交互，作为后续界面变更的参考源。
- 明确 MVP 不包含账号、云同步、跨设备自动同步、提醒、连续天数、长期热力图、备注、分享或社交能力。

## Capabilities

### New Capabilities

- `habit-lifecycle-and-recording`: 管理每日目标习惯，并记录和纠正每日完成量。
- `weekly-execution-review`: 按固定统计口径生成当前周与历史周的执行复盘。
- `local-data-management`: 在单一浏览器内保存、校验、导入和导出习惯数据。
- `responsive-pwa-experience`: 在手机和桌面上提供完整但层级不同的响应式使用体验。

### Modified Capabilities

无。项目尚无已生效的 OpenSpec 能力规格。

## Impact

- 新建浏览器端 Web/PWA 应用、领域计算、页面交互、数据持久化和自动化测试。
- 仅使用浏览器本地存储；不涉及后端 API、账号体系、第三方服务或数据库迁移。
- 后续实现必须以本变更中的 `design.md`、`UI-spec.md`、各能力规格和 `tasks.md` 为准。
